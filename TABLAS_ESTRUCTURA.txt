## TABLA 1: ranks
Ubicación: Migración 019, Schema.sql
Catálogo oficial de rangos por departamento

Estructura:
- department TEXT NOT NULL (hfd, ems, dot, hpd, hcso, ice, tph)
- rank_key TEXT NOT NULL (officer_1, firefighter, trooper_1, etc.)
- rank_label TEXT NOT NULL (Police Officer I, Bombero, etc.)
- hourly BIGINT NOT NULL DEFAULT 0 (por hora IN-GAME)
- sort_order INTEGER NOT NULL DEFAULT 0 (orden de jerarquía)
- min_hours BIGINT NOT NULL DEFAULT 0 (horas requeridas para HFD/EMS/DOT)
- PRIMARY KEY (department, rank_key)

Departamentos:
- HFD: 13 rangos (Recruit Firefighter → Fire Chief)
- EMS: 13 rangos (EMT Trainee → EMS Director)
- DOT: 13 rangos (Trainee → Executive Director)
- HPD: 11 rangos (Officer I → Chief)
- HCSO: 11 rangos (Deputy Sheriff → Chief)
- ICE: 11 rangos (Cadete ICE → Director de ICE)
- TPH: 16 rangos (Probationary Trooper → Trooper Chief)

Usado por:
- assets/auth.js línea 1351: hrpGetRanks()
- js/app.js línea 265: Caché de rangos ordenados por departamento
- manages.html: Sistema de gestión de rangos

## TABLA 4: pay_shift
Ubicación: Migración 019, Schema.sql
ACUMULACIÓN DE PAGO POR TURNO (Sistema nuevo)

Estructura:
- discord_id TEXT PRIMARY KEY
- username TEXT NOT NULL DEFAULT ''
- department TEXT NOT NULL DEFAULT ''
- rank_key TEXT NOT NULL DEFAULT ''
- hourly BIGINT NOT NULL DEFAULT 0 (por hora in-game)
- accrued_seconds BIGINT NOT NULL DEFAULT 0 (consolidados)
- collected_seconds BIGINT NOT NULL DEFAULT 0 (ya pagados)
- active BOOLEAN NOT NULL DEFAULT false (¿en turno?)
- segment_start TIMESTAMPTZ (inicio del segmento actual)
- updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

Lógica:
Pendiente = floor((accrued_seconds - collected_seconds) * hourly / 600)
Conversión: 1 hora real = 6 horas in-game

Usado por:
- RPC hrp_pay_widget(): Calcula dinero pendiente
- RPC hrp_pay_start(): Inicia turno
- RPC hrp_pay_end(): Finaliza turno
- RPC hrp_pay_collect_srv(): Cobra dinero (SOLO service_role)

## FLUJO ACTUAL (Sistema 019-023)

1. OFICIAL INICIA TURNO
   UI (manages.html) → hrpPayStart() → RPC: hrp_pay_start()
   - Busca rank en rank_members
   - Crea/actualiza pay_shift (active=true)
   - Retorna dinero pendiente

2. SISTEMA ACUMULA TIEMPO
   RPC: hrp_pay_widget() (cada vez que se abre dashboard)
   - Lee pay_shift: accrued_seconds + (NOW() - segment_start)
   - Calcula pending = floor((total - collected) * hourly / 600)

3. OFICIAL FINALIZA TURNO
   UI → hrpPayEnd() → RPC: hrp_pay_end()
   - Calcula tiempo transcurrido
   - Suma a accrued_seconds
   - Marca active=false

4. OFICIAL COBRA DINERO
   UI → hrpPayCollect() → Netlify function (rank-admin)
   - Verifica rol en Discord
   - RPC: hrp_pay_collect_srv() (service_role)
   - INSERT economy (suma dinero)
   - INSERT pay_collections (registra cobro)
   - UPDATE pay_shift (marca como collected)

5. ALTO MANDO CAMBIA RANGO
   UI (manages.html) → hrpSetUserRank() → Netlify function (rank-admin)
   - RPC: hrp_rank_set_srv() (service_role)
   - Valida que rango exista en ranks
   - UPDATE rank_members (nuevo rank_key, hourly)
   - UPDATE pay_shift (sella lo acumulado si hay turno activo)
   - INSERT rank_history (registra el cambio)

## FUNCIONES RPC CRÍTICAS

hrp_pay_widget(p_discord_id TEXT)
- Retorna: {active, pending, hourly, department, rank_key, accrued_seconds}
- Uso: Dashboard de dinero
- Seguridad: GRANT anon, authenticated, service_role

hrp_pay_start(p_discord_id, p_username, p_department, p_role_ids)
- Retorna: Estado de turno + datos de sueldo
- Uso: Botón 'Iniciar Turno'
- Seguridad: GRANT anon, authenticated, service_role

hrp_pay_end(p_discord_id TEXT)
- Retorna: {status, active, pending, accrued_seconds}
- Uso: Botón 'Finalizar Turno'
- Seguridad: GRANT anon, authenticated, service_role

hrp_pay_collect_srv(p_discord_id TEXT) - SENSIBLE
- Retorna: {status, amount, balance}
- Verificación: Netlify function (rank-admin)
- Seguridad: GRANT service_role ONLY

hrp_rank_set_srv(p_actor_id, ..., p_department, p_rank_key) - SENSIBLE
- Retorna: {status, discord_id, department, rank_key, rank_label, hourly}
- Verificación: Netlify function (rank-admin)
- Regla: p_actor_id ≠ p_target_id (no cambiarte a ti mismo)
- Seguridad: GRANT service_role ONLY
