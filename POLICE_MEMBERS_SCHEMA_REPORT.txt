## 1. DEFINICIÓN DE LA TABLA

### Estructura Base

La tabla police_members se define en:
- schema.sql (línea 81-94)
- supabase/migrations/001_police_system.sql (línea 30-43)

`sql
CREATE TABLE IF NOT EXISTS police_members (
  discord_id TEXT PRIMARY KEY,
  username TEXT,
  role_id TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
`

### Columnas Actuales

| Columna      | Tipo         | Constraint           | Descripción |
|--------------|--------------|---------------------|-------------|
| discord_id   | TEXT         | PRIMARY KEY          | ID único del usuario en Discord |
| username     | TEXT         | NULL permitido       | Nombre de usuario de Discord |
| role_id      | TEXT         | NOT NULL             | ID del rol de Discord que autoriza acceso |
| created_at   | TIMESTAMPTZ  | NOT NULL, DEFAULT NOW() | Timestamp de creación |

NOTA IMPORTANTE: Solo 4 columnas. Esta tabla sirve para CONTROL DE ACCESO solamente.


## 2. POLÍTICAS DE ROW LEVEL SECURITY (RLS)

RLS está HABILITADO
Política: Totalmente abierta (permite SELECT, INSERT, UPDATE, DELETE para todos)
Implicación: No hay restricciones en nivel de datos

## 4. CAMPOS BUSCADOS POR QUERIES

1. discord_id (PRIMARY KEY) - MÁS FRECUENTE
2. role_id - Común para verificar permisos
3. username - Búsquedas de usuarios
4. * (todas) - Cargas masivas

Filtros comunes:
- eq (equals)
- ilike (case-insensitive LIKE)


## 5. TABLAS RELACIONADAS

police_members NO tiene foreign keys, pero se relaciona con:

- users: Datos generales Discord
- payroll_members: Rango y departamento (NOTA: rank y department están en payroll_members, NO en police_members)
- police_shift_sessions: Sesiones de trabajo
- police_hours_adjustments: Ajustes manuales
- police_records: Registros de arresto/multa


## 6. INDICADORES (INDEXES)

NO hay índices explícitamente creados (solo PK en discord_id).

Recomendación: Crear índices en:
- role_id (muchas búsquedas por rol)
- username (búsquedas por nombre)


## 7. PROBLEMA: Query Lenta o Colgada

Causas Posibles:
1. RLS Policy lenta (aunque es simple)
2. Tabla con locks
3. Índices faltantes (sin índice, SELECT completo es lento)
4. Problema de conexión a Supabase

Diagnóstico (ejecutar en SQL Editor de Supabase):
SELECT * FROM information_schema.columns WHERE table_name = 'police_members';
SELECT COUNT(*) FROM police_members;
SELECT discord_id, username, role_id FROM police_members LIMIT 1;
EXPLAIN ANALYZE SELECT * FROM police_members WHERE role_id = '...';


## 8. RESUMEN EJECUTIVO

Columnas: 4 (discord_id, username, role_id, created_at)
Primary Key: discord_id (TEXT)
RLS: HABILITADO (política abierta)
Foreign Keys: NINGUNO
Índices Explícitos: NINGUNO
Operación Más Frecuente: SELECT por discord_id
Principal Filtro: discord_id, role_id
